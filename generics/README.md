# Go Generics

> Most of the code and documentation in this repo was generated by [Claude](https://claude.ai).

This project demonstrates common use cases for generics in Go (introduced in 1.18).

## When to Use Generics

**You have duplicate functions that differ only by type**

If you find yourself writing `SumInts`, `SumFloats`, `SumStrings` with identical logic, a single generic function eliminates the duplication while keeping type safety.

**You are building a reusable data structure**

A `Stack`, `Queue`, `Cache`, or linked list has logic that is completely independent of what it stores. Generics let you write it once and have the compiler enforce type correctness per instance.

**You are writing utility functions over slices or maps**

Operations like `Filter`, `Map`, and `Reduce` apply the same algorithm to any element type. Without generics these either require code generation or sacrifice type safety with `interface{}`.

**You need to express a constraint beyond `any`**

When a function requires operators (`<`, `>`, `+`) or methods on its type parameter, a constraint interface narrows the allowed types at compile time rather than panicking at runtime.

**You want to encode presence/absence without losing type information**

A generic `Option[T]` or `Result[T]` wrapper avoids the need for `interface{}` and type assertions at every call site.

## When to Avoid Generics

**You only have one concrete type**

If a function or type is only ever used with `int`, just use `int`. Adding a type parameter for a single caller is complexity with no payoff.

**The logic differs across types**

Generics express *identical* logic across types. If the behavior changes per type, an interface with methods is the right tool — the method dispatch is the point.

**You need to inspect or switch on the type at runtime**

If the function body needs to know the concrete type (e.g. `switch v := any(v).(type)`), you are working against generics. Reach for `interface{}` and a type switch instead.

**The code becomes harder to read**

A function signature like `func Merge[K comparable, V1, V2, R any](...)` can be harder to follow than two concrete functions. Clarity for the reader outweighs DRY in these cases.

**You are on Go < 1.18**

Generics are not available before 1.18. Use interfaces or code generation instead.
